# Карта кода Telegram-бота

Этот файл помогает быстро найти нужный участок `bot.py`. Порядок ниже описывает реальное выполнение: от команды запуска до формирования и отправки ответа.

## Быстрый поиск по ключевым словам

В `bot.py` используйте поиск по меткам:

| Метка / ключевое слово                                  | Где искать                         | Что делает                                                  |
| ------------------------------------------------------- | ---------------------------------- | ----------------------------------------------------------- |
| `[STARTUP]`, `__main__`, `main()`                       | Нижняя часть файла                 | Точка входа и запуск Telegram polling                       |
| `[CONFIG: ENV]`, `required_env`, `BOT_TOKEN`            | В начале файла                     | Чтение `.env` и проверка обязательных переменных            |
| `[PLATONUS]`, `authorize`, `journal`, `_fetch_journal`  | Класс `Platonus`                   | Вход, хранение HTTP-сессии, запрос журнала и повторный вход |
| `[GRADES: PARSE]`, `find_subjects`, `average_of`        | Раздел оценок                      | Извлечение предметов и среднего балла из ответа API         |
| `[GRADES: DISPLAY]`, `mark_emoji`, `format_grades`      | Раздел оценок                      | Цвет оценки и форматирование общего списка                  |
| `[SCHEDULE]`, `load_schedule`, `find_avg`, `format_day` | Раздел расписания                  | Чтение JSON, сопоставление уроков с журналом и вывод дня    |
| `[SETTINGS]`, `show_teachers`, `save_settings`          | Раздел настроек                    | Чтение и сохранение настройки показа преподавателей         |
| `[TELEGRAM: HANDLERS]`, `grades_cmd`                    | Раздел Telegram                    | Обработка команд и отправка сообщений                       |
| `teachers_cmd`                                          | Раздел Telegram                    | Команда переключения имён преподавателей                    |
| `relogin_cmd`                                           | Раздел Telegram                    | Команда повторной авторизации Platonus                      |
| `today_cmd`, `marks_for_date`                           | Раздел Telegram и класс `Platonus` | Оценки, датированные сегодняшним днём                       |

## Порядок выполнения при запуске

1. **Импорт библиотек** — загружаются asyncio, requests, python-dotenv и Telegram API.
2. **Окружение** — `load_dotenv()` читает `.env`; `required_env()` проверяет `BOT_TOKEN`, `PLATONUS_LOGIN`, `PLATONUS_PASSWORD`, `ALLOWED_USER_ID`. При пропуске параметра запуск прекращается с пояснением.
3. **Константы и логирование** — задаются адрес Platonus, HTTP-заголовки, параметры семестра и логгер.
4. **Клиент Platonus** — объявляется класс, который умеет войти и запросить журнал. Сам сетевой вход обычно происходит при первой команде `/grades` либо сразу по `/relogin`.
5. **Функции оценок** — объявлены помощники для поиска предметов и среднего балла в полученном JSON.
6. **Настройки** — определяется путь к `settings.json`; функции чтения и записи вызываются при форматировании оценок/расписания и при `/teachers`.
7. **Расписание** — при импорте вызывается `load_schedule()`; `schedule.json` читается один раз, результаты кладутся в `SCHEDULE`, `BELLS`, `ALIASES`.
8. **Создание клиента** — создаётся объект `platonus`. HTTP-запросов до команды пользователя он не выполняет.
9. **Входная точка** — при запуске `py bot.py` вызывается `main()`.
10. **Telegram-приложение** — `main()` создаёт приложение, регистрирует обработчики `/teachers`, `/grades`, `/relogin` и запускает `run_polling()`.

## Дерево команд и вызовов

```text
py bot.py
└── main()
    ├── Application.builder().token(...).build()
    ├── register CommandHandler
    └── run_polling()
        ├── /grades [год семестр | номер дня]
        │   └── grades_cmd()
        │       ├── allowed() — проверка Telegram ID владельца
        │       ├── разбор аргументов команды
        │       ├── asyncio.to_thread(platonus.journal, year, term)
        │       │   └── Platonus.journal()
        │       │       ├── authorize() — если ещё нет сессии
        │       │       └── _fetch_journal()
        │       │           └── при SessionExpired: authorize() и одна повторная попытка
        │       ├── build_lookup() — индекс оценок по предметам
        │       ├── format_grades() — общий список, если день не указан
        │       ├── format_today() / format_day() — расписание
        │       └── reply_text() — отправка частей сообщения до 4000 символов
        ├── /relogin
        │   └── relogin_cmd()
        │       ├── allowed()
        │       ├── asyncio.to_thread(platonus.relogin)
        │       └── reply_text() — результат входа
        ├── /today
        │   └── today_cmd()
        │       ├── дата сегодня в Asia/Almaty
        │       ├── Platonus.marks_for_date()
        │       │   ├── чтение списка предметов и их subjectID/queryID
        │       │   └── GET /subject/... для каждого предмета, фильтр MarkDate
        │       └── форматирование оценок за день
        └── /teachers [on|off]
            └── teachers_cmd()
                ├── allowed()
                ├── load_settings()
                ├── выбрать явное значение или переключить текущее
                ├── save_settings()
                └── reply_text() — подтверждение
```

## Назначение функций по порядку объявления

### Настройка и Platonus

- `required_env(name)` — обязательный параметр из окружения с понятной ошибкой, если он пуст.
- `SessionExpired` — внутреннее исключение, обозначающее, что сервер требует повторную авторизацию.
- `Platonus.__init__(login, password)` — создаёт requests-сессию, сохраняет логин/пароль и блокировку.
- `Platonus.authorize()` — получает cookies, отправляет логин и пароль, сохраняет `personID`, `token` и `sid`.
- `Platonus._fetch_journal(year, term)` — делает HTTP-запрос журнала; проверяет HTTP-ошибки и JSON-ответ.
- `Platonus.journal(year, term)` — потокобезопасно получает журнал, автоматически повторяет вход один раз при истёкшей сессии.
- `Platonus.marks_for_date(year, term, target_date)` — загружает страницу каждого предмета и выбирает записи, у которых `MarkDate` совпадает с нужной датой.
- `Platonus.relogin()` — принудительно создаёт новую сессию.

### Оценки и настройки

- `find_subjects(data)` — рекурсивно ищет список элементов `subjectName` во вложенном ответе API.
- `average_of(subject)` — берёт экзамен `AVG_EXAM_NAME`, иначе первый экзамен; возвращает число или `None`.
- `load_settings()` — читает настройки из `settings.json`; возвращает пустой словарь при отсутствии/ошибке файла.
- `save_settings(settings)` — записывает настройки в JSON.
- `show_teachers()` — возвращает флаг `show_teachers`, по умолчанию `True`.
- `mark_emoji(avg)` — назначает цветной круг оценке. Диапазоны и граничные значения меняются только здесь.
- `format_grades(data)` — формирует отсортированный общий список оценок и делит его на обычную и требующую внимания части.

### Расписание и поиск совпадений

- `norm(s)` — приводит строку к нижнему регистру, схлопывает пробелы, нормализует `ё` к `е`.
- `load_schedule()` — читает `schedule.json` и преобразует дни, пары, звонки и алиасы во внутренние структуры.
- `build_lookup(data)` — создаёт словарь `нормализованное название → средний балл`.
- `find_avg(name, lookup)` — ищет предмет сначала по точному имени, затем по вхождению строки и, в конце, приблизительным совпадением.
- `format_day(day, lookup, header)` — строит строки пар заданного дня, добавляя время, преподавателей и оценку/причину отсутствия оценки.
- `format_today(lookup)` — определяет текущий день в `Asia/Almaty`; в выходные сообщает, что занятий нет.

### Telegram-команды

- `allowed(update)` — пропускает только пользователя с ID из `ALLOWED_USER_ID`; остальные запросы молча игнорируются.
- `grades_cmd(update, context)` — разбирает `/grades`, запрашивает журнал, выбирает нужный формат и отправляет ответ частями.
- `relogin_cmd(update, context)` — запускает `Platonus.relogin()` не блокируя event loop и отправляет результат.
- `today_cmd(update, context)` — команда `/today`; показывает оценки, выставленные в текущую дату по времени Алматы.
- `teachers_cmd(update, context)` — включает/выключает вывод преподавателей и сохраняет выбор.
- `main()` — создаёт Telegram-приложение, связывает команды с функциями и начинает long polling.

## Файлы данных и секреты

- `.env` — токен Telegram, учётные данные Platonus и ID пользователя. Не публикуйте этот файл.
- `schedule.json` — дни, пары, предметы, преподаватели, звонки и словарь сокращений. Загружается при старте процесса.
- `settings.json` — пользовательская настройка `show_teachers`; бот обновляет его через `/teachers`.
- `requirements.txt` — Python-пакеты для запуска.

## Быстрые сценарии изменения

- **Поменять цвет оценки:** найдите `mark_emoji` или `[GRADES: DISPLAY]`.
- **Изменить расписание/преподавателя/звонок:** отредактируйте `schedule.json`, сохраняя JSON-структуру; затем перезапустите бот.
- **Изменить сопоставление предметов:** смотрите `norm`, `ALIASES` в `schedule.json` и `find_avg`.
- **Добавить Telegram-команду:** напишите async-функцию рядом с обработчиками и зарегистрируйте её через `CommandHandler` в `main()`.
- **Поменять правила доступа:** смотрите `allowed()` и `ALLOWED_USER_ID`.
- **Изменить адреса/авторизацию Platonus:** смотрите `BASE`, `HEADERS` и методы класса `Platonus`.
## Уведомления после пары

После инициализации Telegram-приложения фоновая задача проверяет время окончания уроков по `bells` в `schedule.json`. В конце каждой пары бот запрашивает оценки за сегодня только по предметам этой пары и отправляет сообщение в личный чат владельца: найденный балл или «оценки за сегодня нет». Уведомления отправляются, пока процесс бота запущен; при остановленном боте пропущенные уведомления не догоняются.

`MarkDate.Hour` и `MarkDate.Minute` в ответе Platonus могут быть нулевыми и не являются надёжным временем выставления. Поэтому `/today` показывает предмет и балл без времени; время окончания пары берётся отдельно из расписания звонков.
## Ручная проверка уведомления

Из папки проекта выполните:

```powershell
py bot.py --test-notification
```

Бот отправит в Telegram уведомление для первой пары сегодняшнего дня, включая проверку оценки за сегодня по предмету. Для выбора дня и пары используйте, например, `py bot.py --test-notification --day 2 --pair 3` (день: 1=понедельник ... 5=пятница). Это разовый режим: команда отправит сообщение и завершится, не запуская постоянный polling. Для получения сообщения Telegram-бот должен быть доступен по сети, а вы должны ранее открыть с ним личный чат.

Временные сетевые сбои обрабатываются повторными попытками с увеличивающейся паузой. Если проверка/отправка уведомления всё равно завершится тайм-аутом, фоновая задача повторит попытку примерно через минуту, пока сообщение не будет отправлено.
